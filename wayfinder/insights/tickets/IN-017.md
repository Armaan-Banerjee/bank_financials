## Question

Can a user see where every reported number came from and whether it is safe
to compare before relying on a chart?

## Scope

- Expose workbook, sheet, raw label/value, source note, basis note, unit,
  restatement note, period variant, and extraction timestamp.
- Add metric/bank/year coverage, missingness, non-numeric disclosure, duplicate
  or variant-label counts, unit/basis mismatches, and stale-output checks.
- Add HTML diagnostics and a Power BI-friendly quality fact/dimension view.
- Link summary observations to source-note/citation detail through the existing
  deliverable path where possible.

## Completion criteria

- Every derived statistic carries comparable-N and exclusion reasons.
- Quality checks run during refresh and fail clearly on structural corruption.
- The quality view distinguishes genuine non-disclosure from extraction error.

## Progress

Completed on 2026-08-30. Added `in017_quality.py`, which produces a
Power-BI-friendly payload containing row-level lineage facts, bank and metric
dimensions, post-dedup quality facts, refresh metadata, and structural checks.
Lineage retains workbook, sheet, source row label, raw value, period, unit,
reporting basis, restatement note, and source note.

Quality facts distinguish genuine missing disclosure from disclosed-but-unparsed
text, and record numeric, missing, non-numeric, special-value, coverage, unit,
basis, and row-label-variant counts. Refresh checks fail clearly for missing
core tables, orphan metric rows, duplicate metric identity keys, or rows with
no FRN. The payload is generated during the standard refresh before HTML/PDF
generation, and a readable collapsible monitoring and source-trace section is
included in both deliverables.

Resolution: IN-017 completion criteria met. The generated quality payload is
available at `research/in017_quality.json`; 168 tests pass and the complete
145-bank refresh completed successfully.
