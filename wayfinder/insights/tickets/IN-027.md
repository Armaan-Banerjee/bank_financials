## Question

The HTML client deliverable (`build_in005_prototype.py` + `in011_deliverables.py`)
already computes and renders a very rich set of analyses — coverage, CET1
decomposition, robust distributions, bank trajectories with zoom, rank
mobility, quality/coverage heatmaps, source lineage, outliers, parent-group
dispersion, absolute capital/RWA, distribution benchmarks, and the IN-021
regulatory headroom table — but it reads as a long stack of collapsed
`<details>` cards rather than a dashboard: nothing at the top tells a reader
what needs attention, the sidebar nav only links 4 of ~13 sections, and each
section reinvents its own local search box. The user asked for it to "look
more like a proper dashboard" and reviewed a set of proposed additions before
opening this ticket.

**Why this is genuinely new, not a restatement of an existing ticket:**

- IN-011 owns rendering the existing sections but never recombines their
  outputs into a single cross-cutting view — each of IN-009 (outliers),
  IN-021 (headroom status), and IN-017/IN-025 (quality flags) render their
  own independent table today.
- No ticket currently produces a bank-level "profile" view; every existing
  section is metric-first, not bank-first.
- No ticket computes an aggregate cross-bank trend sparkline (e.g. median
  CET1/leverage/NSFR by year) for the top-of-page summary; IN-011's trend
  bars are metric/period-selectable but not a compact always-visible summary.

## Scope/seams

- **Watchlist panel** (top-of-page, above the existing KPI strip): a ranked
  "banks to review" list built by recombining already-computed payloads —
  IN-009's `outliers` (broad+strict), IN-021's `screened` headroom records
  with adverse status, and IN-017/IN-025's quality/flag counts. This is pure
  recombination in the HTML layer (or a small new adapter function in
  `in011_deliverables.py` if the join logic is non-trivial) — do not
  re-derive outlier/headroom/quality logic; import and reuse the existing
  functions/payloads exactly as the rest of IN-011 already does. Each row
  must link/scroll to the section and bank that produced it, and must show
  *why* it's flagged (reason text already present in each source payload).
- **Full section navigation**: expand the dashboard sidebar
  (`decorate_dashboard_html`'s `navigation` string) to link every major
  section currently rendered by `render_html_analysis` (coverage, ratio
  decomposition, distribution visuals, trajectories, quality views,
  outliers, parent-group dispersion, absolute analysis, distribution
  benchmarks, headroom, interim coverage) via stable anchor ids — most
  `<details>` blocks already have distinguishable content but need a stable
  `id` added to their wrapping `<details>`/`<summary>` structure. Open the
  highest-priority 2-3 sections by default (headroom, outliers, watchlist)
  instead of everything collapsed.
- **Unified bank search/filter**: one global search input (sidebar or
  header) that filters/highlights matching rows across every section that
  currently has its own local filter (in023's coverage filter, in024's
  bank/metric filter, in025's filter) — consolidate the existing per-section
  filter JS into one shared filter that drives all of them via a common
  `data-search` attribute convention (already used ad hoc in in023/24/25;
  standardize it, don't invent a second convention).
- **Bank drill-through**: clicking a bank name anywhere in the deliverable
  opens a slide-over/panel showing that bank's full ratio history (from
  IN-009's series), current headroom (IN-021), and any flags (outliers/
  quality) in one place. Client-side only — build this from data already
  embedded in the page's `D`/`in011` JSON payload, no new Python data model
  needed unless assembly turns out to require a shape none of the existing
  payloads provide (if so, note the minimal shape needed and add it to
  IN-011's adapter, not a new top-level script).
- **Trend sparklines** in the KPI strip: median CET1/leverage/NSFR (or
  similar headline ratios) by fiscal year, computed from IN-009's existing
  `trend_series`/coverage data already loaded into the page — small SVG
  sparkline per metric, consistent with the existing hand-rolled SVG style
  used elsewhere in this file (no charting library, matching
  `CODING_STANDARDS.md` and the rest of the file's approach).
- **Data-freshness badge**: surface the refresh/trace-completeness metadata
  already computed by IN-025 (e.g. `trace_completeness`, cadence counts) as
  a small badge near the KPI strip — no new computation, just surfacing an
  existing figure.
- Apply the same additions to `build_in006_pdf.py` only where they translate
  meaningfully to a static PDF (e.g. the watchlist panel as a summary table,
  the freshness badge as a header line) — the drill-through and live search
  are HTML-only and explicitly out of scope for the PDF.
- **Explicitly out of scope for this ticket**: no new analytical computation
  (no new statistics, no new metric derivations) — this ticket is
  presentation/recombination of already-computed payloads. If reviewing the
  watchlist join surfaces a genuinely missing analytical primitive, note it
  as new fog on the map rather than building it inside this ticket.

## Completion criteria

- A watchlist/alerts panel renders at the top of the HTML deliverable,
  combining IN-009 outliers, IN-021 adverse headroom status, and IN-017/
  IN-025 quality flags, with reason text and links/anchors into the
  relevant section, sourced entirely from existing payloads (no re-derived
  logic).
- The sidebar nav links every major analysis section with stable anchors;
  the highest-priority sections are expanded by default.
- One global bank search/filter works across every section that previously
  had its own independent filter box.
- Clicking any bank name opens a drill-through view combining that bank's
  ratio history, headroom, and flags.
- KPI strip includes trend sparklines for at least the core ratios and a
  data-freshness badge, both computed from existing payload data.
- `build_in006_pdf.py` gets the PDF-appropriate subset (watchlist summary,
  freshness line) using the same shared data, not a separately maintained
  copy.
- `test_pipeline.py` gains assertions that the HTML deliverable contains the
  watchlist panel, the expanded nav anchors, and the freshness badge, and
  that no internal ticket IDs/debug strings leak into client-facing text.
- Full insights test suite stays green; `scripts/insights/README.md` and
  this map's Decisions-so-far are updated on close.

## Resolution

Implemented 2026-08-31. Added the cross-cutting HTML watchlist, full analysis
navigation with stable anchors, default-open outlier/headroom sections, a
global bank search, bank drill-through side panel, freshness badge, and
payload-driven CET1/leverage/NSFR median sparklines. The PDF now includes the
watchlist counts and evidence-freshness line. Added pipeline assertions for
the dashboard contract and ticket-ID leakage, updated the insights README and
map, rebuilt the HTML/PDF pack, validated all embedded scripts, and verified
the complete 219-test suite.
