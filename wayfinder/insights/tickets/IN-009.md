## Question

Build the first vertical slice of the agreed insights improvements. It must
make the four core ratios analytically safer and produce reusable outputs for
later parent-group and deliverable tickets:

- CET1 Ratio
- Tier 1 Ratio
- Total Capital Ratio
- Leverage Ratio

The slice covers evidence-backed normalization, strict and broad
comparability, adjacent-year and long-run movement, and explainable outlier
flags. It must continue to use `research/insights.db` as the source of truth.

## Scope

1. Normalize fiscal-year keys and period metadata without erasing shortened
   periods, entity/basis annotations, or restatement markers.
2. Preserve special disclosures (for example `999999%` LCR) as explicitly
   classified values rather than silently treating them as ordinary finite
   observations. The core-ratio implementation should establish the reusable
   value-status shape for later metrics.
3. Populate reporting-basis metadata only where workbook text explicitly
   supports it at metric or whole-workbook scope. Unknown basis remains
   unknown and is excluded from strict comparisons.
4. Provide strict and broad comparison modes with exclusion/coverage counts.
5. Provide adjacent-year and available long-run movement statistics.
6. Flag outliers using documented percentile, robust-score, movement, and
   domain rules. Every flag includes a reason, source year, and comparability
   status.
7. Produce machine-readable outputs and a quality/comparability report for
   IN-010 and IN-011. New figures must be computed from the database.

## Interface/seam

Create a small normalization/analysis module under `scripts/insights/` with a
stable interface that accepts database-shaped rows and returns normalized
observations, coverage diagnostics, trend results, and outlier results. Keep
SQLite loading and HTML/PDF formatting outside this module so it remains a
deep, testable module with one analysis seam.

## Tests and completion criteria

- Add tests before implementation, one vertical slice at a time, at the
  module's public interface.
- Test period normalization, explicit basis propagation, unknown-basis strict
  exclusion, special-value classification, adjacent/long-run movement,
  percentile/robust-score/domain outliers, and coverage reconciliation.
- Existing insights tests remain green.
- The live database can be refreshed without losing existing fields or
  changing unrelated outputs.
- A human-readable report explains strict/broad counts and every exclusion
  category.

## Progress

Claimed for implementation on 2026-08-30. Created the dependency graph and
implemented the first red-green slices in `scripts/insights/in009_analysis.py`:
