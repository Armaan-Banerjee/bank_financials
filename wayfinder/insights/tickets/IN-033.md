## Question

The user asked (2026-09-01, after IN-029 through IN-032 were closed) to check
through the codebase thoroughly again to ensure no bugs remain. Ran 4 parallel
read-only audit forks covering (1) the core `scripts/insights/` analysis
modules, (2) the deliverable build scripts, (3) the bank-workbook library and
recently-touched build scripts, and (4) the live generated HTML/PDF
deliverables — each explicitly told not to re-report anything IN-029–032
already fixed. Three independent findings survived, one confirmed by 3 of the
4 forks separately.

## Finding 1 — 3 dead no-op `.replace()` calls left over in `decorate_dashboard_html()`

`build_in005_prototype.py`, formerly lines 309, 311-312 (now removed). Same
failure shape as IN-030's root cause (a fix-looking `html.replace()` whose
target string never exists in `html` at that point), but confirmed harmless
this time — each was superseded by a later, correctly-matching replace in the
same function, so today's output was already correct. Verified by simulating
each replace target against the real `TEMPLATE` string and the actual
generation-order mutations before removing them, not just visual inspection.

## Finding 2 — `in020`/`in021`'s "must agree" regulatory-floor guard could silently diverge

`in020_regulatory_context.py`'s `match_context()` and
`in021_headroom_trajectory.py`'s `applicable_context()` both compute
`minimum + buffer_value` from the same `CONTEXT` table and are documented (in
comments added during IN-029's fix) as needing to agree on what counts as "no
floor." But `in020` guarded on `floor == 0` (the combined minimum+buffer) while
`in021` guarded on `minimum == 0` alone — currently equivalent only because no
metric in `CONTEXT` today has a `buffer` record without an accompanying
`regulatory_minimum` record for the same metric/period. A future CONTEXT entry
with only a buffer (no separate minimum) would have matched in `in020` but
silently returned "context_unavailable" in `in021`.

## Finding 3 — 10 build scripts had real source URLs on hand but never wired them into `add_wide_interim_sheet()`'s `hyperlink_cells`

Of the 12 build scripts calling `add_wide_interim_sheet()`, only
`build_rbc_europe.py` and `build_secure_trust.py` passed `hyperlink_cells`
before this fix (IN-031 also fixed NatWest Markets and SMBC). The other 10 —
Aldermore, Co-operative Bank, HSBC UK Bank plc, Investec Bank, Lloyds Bank
Corporate Markets, Lloyds Bank, Metro Bank, National Westminster Bank plc,
Nomura Bank International, Paragon — never wired `hyperlink_cells` through at
all, even though every one of them already had real per-row or per-period
source URLs sitting in the same script (either baked directly into the row's
column-6 text, or in a separate `*_URL`/`INTERIM_SOURCES` constant used
elsewhere in the file). Since IN-031 removed `add_wide_interim_sheet()`'s old
"fall back to plain-text label as a fake hyperlink" behavior, these 10 banks'
interim citation cells were rendering as correctly-non-deceptive but
genuinely un-clickable plain text — a real citation-quality gap IN-031's own
"swept all 145 workbooks, no other bank affected" check didn't catch, because
that sweep looked for *invalid* hyperlinks, not *missing* ones.

## Resolution (2026-09-01)

- Removed the 3 confirmed-dead no-op `.replace()` calls from
  `decorate_dashboard_html()`.
- Aligned `in021_headroom_trajectory.py`'s `applicable_context()` to guard on
  `floor == 0` (the combined minimum+buffer), matching
  `in020_regulatory_context.py`'s `match_context()` exactly, with a comment
  explaining why.
- Wired `hyperlink_cells` through in all 10 affected build scripts, using
  each script's own already-correct URL data (no new external research
  needed — same root-cause shape as IN-031's NatWest Markets fix). Rebuilt
  all 10 workbooks.
- Verified across every one of the 145 workbooks with an Interim Pillar 3
  sheet: 0 source-register cells and 0 matrix value cells with a real URL
  behind them are missing a hyperlink. `verify_workbook.py` re-run against
  representative banks (Aldermore, Paragon) shows genuine non-zero
  `value hyperlinks: N/N` counts, not silence.
- Full suite: 231 tests passing; live `refresh_all.py` clean; regenerated
  HTML deliverable re-checked structurally (`<section>` balance 5/5, all
  watchlist/freshness/sparkline/search CSS present) - no regression from the
  earlier IN-030 fix.
- No other new bugs found in this pass across `in009_analysis.py`,
  `in010_parent_groups.py`, `in016_distribution.py`, `analyze_trends.py`,
  `analysis_queries.py`, `extract_metrics.py`, `build_in006_pdf.py`,
  `export_parent_group_tables.py`, `cluster_banks.py`, `in011_deliverables.py`,
  `in025_quality_views.py`, `refresh_all.py`, `bank_workbook.py`, or
  `verify_workbook.py`.
