## Finding 1 — `extract_metrics.py`'s `main()` can't detect its own partial-extraction failure

Per-workbook exceptions are correctly caught, logged to stderr, and the
extraction continues (documented, intentional — README: "a corrupt/unreadable
file is skipped and logged, not a crash") and errors ARE printed to stdout at
the end. But `main()` calls `_db.validate(conn, expected_banks=n_banks, ...)`
(line ~744) passing `n_banks` — the count *actually written this run* — as
its own expectation, not a true independent expected value (e.g. a hardcoded
145, or a count read from `Banks List 2608.xlsx` minus the known 3 skips). If
a workbook throws during processing, the database ends up with (say) 144
banks, `validate()` is satisfied because it's checking the reduced count
against itself, and the script exits 0. `refresh_all.py` only stops on
non-zero exit codes, so a single failed workbook would currently propagate
silently through the entire refresh and both deliverables with no hard
failure anywhere in the pipeline — only a printed stderr line nothing else
reads.

**Fix direction**: pass a true independent expected count into `validate()`
(the known 145, or derived from the source bank list minus documented skips),
or have `main()` explicitly `sys.exit(1)` if any per-workbook error was
recorded, before declaring success.

## Lower-severity edge cases (fix opportunistically, not urgent)

- **`cluster_banks.py` (lines ~284, 291)** can raise `max() arg is an empty
  sequence` if `n_included - 1 < k_min` (very few banks pass the coverage
  threshold, so `range(k_min, k_max+1)` is empty and `results` stays `{}`).
  Not reachable at the current 145-bank scale; add a guard/explicit error
  message for if this pipeline is ever run against a much smaller subset.
- **`in016_distribution.py`'s panel rank assignment (lines ~188-198)**
  contains dead code: `"rank" in start_map[frn]` is always `False` (nothing
  ever sets a `"rank"` key), so a ternary always takes its `None` branch —
  harmless today only because a second, unconditional loop always overwrites
  it. Clean up so a future refactor of the second loop doesn't silently
  reintroduce a real bug.
- **`in009_analysis.py`'s `detect_outliers()` (line ~366)**: when MAD=0 (more
  than half the latest values are exactly equal), the robust-z-score check is
  silently skipped rather than recording an explicit "insufficient variance"
  state. The two other independent outlier checks (percentile bounds,
  movement) still run, so this isn't a coverage gap, just a missing explicit
  status worth adding for clarity.
- **`extract_metrics.py`'s `parse_numeric()` (line ~232)**:
  `isinstance(value, (int, float))` also matches Python `bool` (bool
  subclasses int), so a stray boolean cell value would silently parse as
  1.0/0.0. Essentially unreachable for real spreadsheet cell values; add an
  explicit `bool` exclusion for correctness's sake.
- **`in009_analysis.py`'s `_metric_observations()` (lines ~399-410)** — used
  only as a pre-filter inside `build_in009_payload` before the properly-fixed
  selector runs — requires the literal word "ratio" in the label for
  CET1/Tier1/Total Capital sheets and excludes any label containing
  "exposure" for Leverage. A genuine percentage row with atypical phrasing
  would be silently dropped before the good selector ever sees it
  (undercoverage, not a wrong value, but still worth loosening or removing
  this redundant pre-filter given `_select_metric_observations` already does
  the real, correct filtering downstream).

## Resolution (2026-09-01)

- Finding 1 fixed: `extract_metrics.py`'s `main()` now passes
  `expected_banks=len(paths) - len(errors)` (a true independent count) to
  `_db.validate()`, instead of `n_banks` (the count it just wrote checked
  against itself). Added a regression test exercising the exact scenario the
  old code couldn't catch: two source workbooks resolving to the same FRN
  (no exception raised, no entry in `errors`, but `write_banks_and_metrics()`
  silently collapses them to one `banks` row) - confirms the old
  self-referential check would have passed trivially and the new one
  correctly raises. The existing corrupt-workbook-continuation test (which
  legitimately expects `returncode == 0` when a workbook throws and is
  correctly excluded from `errors`) still passes unchanged, since that
  scenario's `len(paths) - len(errors)` already equals the real bank count.
- All 4 lower-severity edge cases fixed:
  - `cluster_banks.py` now raises a clear `ValueError` instead of crashing on
    `max() arg is an empty sequence` when too few banks pass the coverage
    threshold for the requested k-range.
  - `in016_distribution.py`'s dead `"rank" in start_map[frn]` check (always
    `False`, since `_ranked()` never sets a `"rank"` key) replaced with a
    plain `None` placeholder and an explanatory comment.
  - `in009_analysis.py`'s `detect_outliers()` now documents (via comment)
    why the MAD=0 case is intentionally skipped rather than silently
    unexplained - the two other independent outlier checks still cover it.
  - `extract_metrics.py`'s `parse_numeric()` now explicitly excludes `bool`
    before the `isinstance(value, (int, float))` check (bool subclasses int
    in Python).
  - `in009_analysis.py`'s `_metric_observations()` redundant/lossy pre-filter
    was removed as part of IN-029's fix (same root cause, same fix - see
    IN-029's resolution).
- Full suite: 231 tests passing; live `refresh_all.py` runs clean.
