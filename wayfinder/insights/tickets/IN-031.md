## Question

A 2026-09-01 audit of `scripts/bank_workbook.py`/`scripts/verify_workbook.py`
and an automated structural sweep of all 146 build scripts and 145 generated
workbooks found two real, confirmed bugs in the bank-build phase's own
verification tooling — worth fixing even though that phase is otherwise
closed, since this tool is the thing that's supposed to catch exactly this
class of problem.

## Bug 1 — `verify_workbook.py`'s wide-format Interim Pillar 3 structural checks never execute

`main()`, lines ~56-118. All the wide-format validation logic (metric/period
counts, missing-field checks, source-register/hyperlink checks) sits nested
**inside** `if headers == expected_headers:` — the long-format branch — not
in a sibling `else`. Every interim sheet actually built today uses the wide
matrix format (per the project's own 2026-08-29 "wide interim-layout
conversion" of all then-eligible workbooks), so `headers == expected_headers`
is always `False` for real data and the entire block, including code clearly
written for the wide-format case, is silently skipped. Verified empirically
against a real workbook — running the verifier against
`NATWEST MARKETS FINANCIALS.xlsx`'s Interim Pillar 3 sheet produces zero
output under "Interim Pillar 3 structure": no format detected, no
metric/period counts, no warnings. Every wide-format interim sheet in the
project (NatWest Markets, NatWest, Nomura, RBC Europe, SMBC, Aldermore,
Co-operative Bank, Investec, Paragon, Secure Trust, and any other bank with
an interim tab) currently gets **zero structural verification** from this
tool despite its docstring's claims.

**Second-order landmine in the same dead branch**: even if this were reached,
lines ~74-78 reference `wide_headers` unconditionally after it's only
assigned inside the `else` of `if missing_fields:` — a genuine
`UnboundLocalError` waiting for a long-format sheet with any missing required
field. And even without missing fields, the same clause would then wrongly
re-check the long-format header row against wide-format headers and print a
false "!! expected long headers ... or wide headers" warning on an actually
valid long-format sheet. This whole clause reads like a merge/refactor error,
not intentional double-checking.

## Bug 2 — 342 of 1,409 interim hyperlink cells fall back to plain text instead of a real URL

`add_wide_interim_sheet()` in `bank_workbook.py`, line ~388:
`source_url = hyperlink_cells.get((row_index, 6), source)` falls back to the
plain source-document label text (e.g. `"Q3 2022 Pillar 3 Supplement"`) as
the hyperlink target when a build script doesn't supply an explicit URL for
that row. openpyxl writes this as-is into `cell.hyperlink`, producing an
invalid (non-http) link that Excel will either error on or mistreat as a
relative path. A full scan of every hyperlink cell in every workbook's
Interim Pillar 3 sheet found **342 of 1,409 (24%)** are non-URL targets,
concentrated in **NatWest Markets FINANCIALS.xlsx** and
**SMBC FINANCIALS.xlsx**. This contradicts the project's own
"Final-audit citation remediation" record in `Build Effort Review Codex.md`,
which reported RBC Europe at 97/97 and Secure Trust at 37/37 fully linked —
NatWest Markets and SMBC were apparently never swept the same way, or
regressed since.

## Scope/seams

- Fix bug 1 by making the wide-format branch a real `elif`/`else` sibling of
  the long-format check (not nested inside it), and fix the `wide_headers`
  reference to only run in the branch where it's actually assigned. Re-run
  the verifier against every workbook with an interim sheet afterward and
  confirm real structural output appears (not silence) for each.
- Fix bug 2 by sourcing real citation URLs for NatWest Markets' and SMBC's
  interim rows that currently lack one — this needs actual research (the
  original source documents), not a code fix alone; treat it the same as the
  original "Final-audit citation remediation" pass did for RBC Europe/Secure
  Trust. If a specific row's real URL genuinely can't be found, leave it
  explicitly blank/documented rather than falling back to non-URL text
  (change `add_wide_interim_sheet()`'s fallback behavior too, so this
  specific failure mode can't recur silently for a future bank).
- Since this is a workbook/build-tooling fix, not an insights-pipeline
  script, it doesn't need `refresh_all.py`/insights-test-suite verification
  — but do rebuild the 2 affected workbooks and re-run `extract_metrics.py`'s
  refresh afterward if any workbook byte content actually changes, to keep
  `insights.db` in sync.

## Completion criteria

- `verify_workbook.py` produces real structural output (not silence) for
  every bank's wide-format Interim Pillar 3 sheet.
- The `UnboundLocalError` landmine in the long-format branch is fixed.
- NatWest Markets and SMBC's interim hyperlink cells are either real URLs or
  explicitly documented as unavailable — 0 non-URL hyperlink cells masquerading
  as real ones.
- `add_wide_interim_sheet()` no longer silently falls back to non-URL text as
  a hyperlink target for future banks.
- This map's Decisions-so-far updated on close.

## Resolution (2026-09-01)

- **Bug 1 fixed**: `verify_workbook.py`'s wide-format branch is now a real
  `else` sibling of the long-format `if`, not nested inside it - confirmed
  it now prints real structural output ("Format: wide; metrics: 11;
  periods: 13; ...") for both NatWest Markets and SMBC, instead of silence.
  The `wide_headers` `UnboundLocalError` landmine is gone (it's now only
  referenced inside the branch that assigns it).
- **Bug 2 fixed at the root, in `bank_workbook.py`**: `add_wide_interim_sheet()`
  now only ever hyperlinks a cell to a value starting `http://`/`https://` -
  a non-URL fallback (previously the plain source-document label text) is
  simply left as unstyled plain text instead of a fake-looking broken link,
  so a future bank missing a real URL is visibly incomplete rather than
  silently wrong.
- **Root cause for the 342 broken cells turned out to be simpler than
  expected**: both `build_natwest_markets.py` and `build_smbc.py` already
  had real, correctly-sourced per-period URLs on disk. `build_smbc.py`
  already wired them into `hyperlink_cells` correctly - its workbook was
  simply **stale** (built before that wiring was added, never rebuilt since).
  `build_natwest_markets.py`'s `INTERIM_SOURCES` dict had the real URLs but
  never threaded them into `add_wide_interim_sheet()`'s `hyperlink_cells`
  parameter at all - fixed by building an `interim_hyperlinks` dict
  alongside `interim_rows` and passing it through, the same pattern
  `build_smbc.py` already used correctly.
- Verified every one of the 22 distinct source URLs resolves live (HTTP 200,
  `content-type: application/pdf`) before using them - both from
  `build_natwest_markets.py`'s own existing `INTERIM_SOURCES` and from a
  research pass that (redundantly, as it turned out) independently found
  the same SMBC URLs already present in `build_smbc.py`.
- Rebuilt both workbooks: **NatWest Markets 150/150 and SMBC 192/192
  interim hyperlink cells are now real URLs (0 non-URL)** - the full 342
  reported by the audit are fixed.
- Swept all 145 workbooks with an Interim Pillar 3 sheet for the same
  pattern - no other bank affected.
- `verify_workbook.py` re-run against both rebuilt workbooks: 14 sheets, 2
  charts, wide-format Interim Pillar 3 structure now genuinely checked (not
  silently skipped). The cash-flow-tail reconciliation warnings it also
  prints for both banks are the tool's own pre-existing, documented
  false-positive pattern (opening/closing-cash and FX-translation rows) -
  unrelated to this fix, not a regression.
- Live `refresh_all.py` and the full insights test suite (231 tests) confirmed
  clean after the rebuild.
