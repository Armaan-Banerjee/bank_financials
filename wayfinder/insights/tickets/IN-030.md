## Question

The user asked (2026-09-01) for an aggressive audit of all code plus
verification that the deliverables match visual expectations. No headless
browser exists in this environment, so verification used the closest
provable proxy — parsing the generated HTML/CSS/JS directly and confirming
structurally whether elements would render as intended — rather than an
actual screenshot. That proxy found real, confirmed defects, not just
suspected ones:

## Bug 1 — IN-027's watchlist panel, freshness badge, and sparklines have NO matching CSS anywhere in the file

`wayfinder/insights/deliverable/uk_bank_insights.html`'s
`dashboardWatchlist()`/`dashboardKpis()`/`dashboardSparklines()` JS functions
generate elements using class names `.watchlist-grid`, `.dashboard-watchlist`,
`.watchlist-item`, `.watchlist-row`, `.freshness-badge`, and
`.kpi-sparkline` — **zero occurrences of any of these as CSS rules exist
anywhere in the page**, and there is no dynamic style-injection mechanism
(`createElement("style")`) either. This means the watchlist (meant to be a
styled panel/grid) currently renders as plain unstyled stacked divs, and the
freshness badge (meant to be a pill/badge) renders as plain unstyled text.

**This directly contradicts IN-027's own Resolution section**, which claims
"Added the cross-cutting HTML watchlist... freshness badge, and
payload-driven CET1/leverage/NSFR median sparklines... validated all
embedded scripts, and verified the complete 219-test suite" — the test suite
apparently verified the JS *executes* and produces the right elements/data,
but nothing verified those elements are actually *styled*, which is the
entire point of a ticket titled "make it look like a proper dashboard." This
is the single most user-visible finding of the whole audit given the user's
specific ask.

## Bug 2 — `<section id="overview">` never closes; the fix code for it is dead

`build_in005_prototype.py`'s `decorate_dashboard_html()` (line ~262) tries to
add the missing closing tag by string-replacing the literal
`'</article></section>\n__IN011_ANALYSIS__'`, but `main()` (line ~231)
already substitutes `__IN011_ANALYSIS__` with real rendered content **before**
calling `decorate_dashboard_html()` (line ~232) — so that literal placeholder
string no longer exists in the HTML by the time the replace runs, making it a
silent no-op. Confirmed directly in the live generated file: 5 `<section>`
opens, only 4 closes. Practical visual impact is currently low (nothing in
the page's CSS/JS depends on sibling-level `<section>` nesting — only
`scroll-margin-top` on the element itself, which still works regardless) but
it's a real, confirmed markup defect with genuinely dead fix code sitting
next to it.

## Bug 3 — main JSON payload not escaped against a literal `</script>` substring

`build_in005_prototype.py` line ~225: `data = json.dumps(payload,
separators=(",", ":"))` has no `.replace("</", "<\\/")` escaping, unlike the
equivalent, smaller in022 payload in `in011_deliverables.py` line ~302 which
correctly does this. Currently safe only because no bank name/source-note/
citation string in the live 145-bank dataset happens to contain the literal
substring `</script` — but this is exactly the kind of hand-transcribed
free-text field (source notes, citation text) that has already produced
unexpected characters elsewhere in this project. Fix proactively; the correct
pattern already exists in the same codebase, just apply it consistently.

## Bug 4 — PDF cover page has a hardcoded, now-stale date

`build_in006_pdf.py` line ~163:
```python
f"UK BANK INSIGHTS - {headline.upper()}", "Fixed snapshot | 29 August 2026", "",
```
Every other figure in this file is explicitly computed fresh per
`CODING_STANDARDS.md`'s rule against hardcoding data-derived figures — the
file's own docstrings say so repeatedly — but the cover page's own date is a
literal string. The PDF has been regenerated many times since 2026-08-29
(including via multiple `refresh_all.py` runs on 2026-09-01) and still claims
"29 August 2026" on the first page a reader sees. This is currently, visibly
wrong on a client-facing document today, not a latent risk.

## Bug 5 — PDF legend-position lookup can silently misplace overlapping labels

`build_in006_pdf.py` line ~338:
```python
commands += _pdf_text(metric, x + width + 12, y - 12 - chart["trends"].index((metric, values)) * 16, 8)
```
`.index()` searches by equality on the `(metric, values)` tuple and returns
the position of the *first* match. If two metrics in `chart["trends"]` ever
produce identical `values` lists (a real possibility, not hypothetical, since
`values` come from `median()` over possibly-empty per-year cohorts and two
metrics with no data for the plotted years would both be all-`None`), the
second metric's legend label silently renders at the first metric's
y-position, overlapping it. Low severity, narrow trigger condition, but a
real bug with a trivial fix (use the loop index, not `.index()`).

## Resolution (2026-09-01)

**Root cause was deeper than the 5 listed bugs**: `TEMPLATE` in
`build_in005_prototype.py` had a *stale, pre-`decorate_dashboard_html()`
duplicate* of the dashboard shell baked directly into it (an old snapshot
from before the 9-link nav, watchlist, global search, or sparklines existed
- only 4 nav links, no watchlist/freshness/sparkline CSS at all). Because
that duplicate already contained `</style></head><body><main>`'s successor
markup, `decorate_dashboard_html()`'s very first `html.replace('</style>
</head><body><main>', ...)` never matched anything, which silently killed
**every** patch downstream of it in that function - not just the CSS, but
the 9-link nav, the global search box, and (via a second dead replace
targeting the old 4-link nav) the global-search div specifically. This is
why the live deliverable had 0 occurrences of `.dashboard-watchlist{`,
`.watchlist-grid{`, `.watch-item{`, `.freshness-badge{`, `.global-search{`,
and `.bank-drillthrough{` despite `decorate_dashboard_html()` appearing to
define all of them - and why IN-026/IN-027's own "verified" claims didn't
catch it: their test coverage checked that class-name *strings* appeared
somewhere in the page (e.g. in the JS that generates them), never that a
matching CSS *rule* existed.

- Removed the stale baked-in duplicate from `TEMPLATE`, restoring the clean
  `</style></head><body><main>` seam `decorate_dashboard_html()`'s own
  docstring says it expects - it is now genuinely the single source of truth
  for the dashboard shell again.
- Merged the dead second nav-upgrade replace (which searched for an old
  4-link nav that was never actually inserted) directly into the
  `navigation` string itself, so the global-search box is built once, not
  patched in by a step that could never fire.
- Added the missing `.kpi-sparkline` CSS rule (the one class genuinely never
  defined anywhere, even before the TEMPLATE bug was found).
- Fixed the unclosed `<section id="overview">`: the old fix anchored on the
  literal `__IN011_ANALYSIS__` placeholder (already substituted away by the
  time `decorate_dashboard_html()` runs) and, once that was corrected, on an
  assumed direct adjacency to `</article></section>` that also didn't exist
  (two `<style>` blocks sit in between). Now anchors on the unique, already-
  produced `<section id="analysis" class="grid in011-analysis">` string
  instead of guessing what precedes it.
- Escaped the main JSON payload against a literal `</script>` substring,
  matching the pattern already used for the smaller in022 payload.
- PDF cover date is now computed from the database's own `metrics_built_at`
  refresh metadata (`_snapshot_date_label()`), not a hardcoded literal -
  confirmed the regenerated PDF now shows "1 September 2026".
- PDF legend labels now use the loop's own index instead of
  `.index((metric, values))`, which could silently overlap two metrics
  sharing an identical (e.g. all-`None`) values list.
- Regression tests added: CSS-rule presence (not just class-name-string
  presence) for all 7 previously-unstyled classes, `<section>` open/close
  balance, the computed snapshot date, and the legend-overlap fix. Verified
  end to end against a live `refresh_all.py`: `<section>` open/close now
  5/5 (was 5/4), all 7 CSS rules present exactly once each, all 10 nav
  anchors and their matching section ids present, global search box present.
- Full suite: 231 tests passing.
