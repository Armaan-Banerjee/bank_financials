## Question

How can the HTML pack feel like a focused banking-analysis dashboard rather
than a long webpage, while keeping the detailed evidence and visual analysis?

## Scope

- Rework the HTML page hierarchy into a dashboard-style layout inspired by
  Power BI and modern data-analysis products, without requiring Power BI
  deployment or changing the Python-first pipeline.
- Add a clear executive overview with compact KPI cards, key signals, data
  coverage/quality indicators, and prominent period or metric context.
- Improve navigation between overview, trends, peer comparisons, movement,
  regulatory context, and source-quality sections.
- Establish a consistent visual system for cards, filters, legends, tables,
  chart containers, status badges, spacing, typography, and colour semantics.
- Keep existing interactive controls, accessible table fallbacks, explanatory
  text, source traceability, and the controlled PDF output working.
- Make the layout usable on common laptop widths and reasonably responsive on
  smaller screens; avoid introducing a frontend build dependency unless it is
  clearly justified.

## Completion criteria

- The first viewport communicates the main cross-bank conclusions and data
  caveats without requiring the reader to scan the full page.
- Sections have a coherent dashboard navigation model and visually distinct
  analytical modules, with no loss of existing chart interactions or filters.
- KPI cards and status styling are derived from the existing generated payloads;
  no values are duplicated manually in HTML/CSS.
- The page remains accessible: keyboard navigation, readable contrast,
  descriptive chart/table labels, and non-colour-only status meaning are kept.
- HTML and PDF generation remain deterministic; the PDF is either unchanged
  or receives only deliberate presentation-safe adjustments.
- Focused rendering/interaction tests and the full insights test suite pass.

## Out of scope

- Deploying a live Power BI report or adding a Power BI service dependency.
- Changing the underlying bank data, metric definitions, statistical methods,
  or evidence-quality rules.

## Resolution

Implemented 2026-08-31. Added a dashboard-style HTML shell with persistent
analytical navigation, executive KPI cards derived from the generated payload,
an overview landmark, clearer section anchors, responsive layout behaviour,
and dashboard-oriented colour, card, focus, and spacing treatment. Existing
interactive charts, filters, collapsible analysis sections, accessible labels,
source traceability, and the controlled PDF output remain intact. Added
dashboard-shell contract tests, rebuilt the HTML/PDF pack, validated all
embedded scripts, and verified the complete 219-test suite.
