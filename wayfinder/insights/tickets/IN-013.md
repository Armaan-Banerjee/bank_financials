## Question

Create the shared analysis-query layer so HTML, PDF, diagnostics, and future
analyses use one tested interface over `research/insights.db`.

## Scope/seams

- Comparability and filtering queries.
- Trend and movement queries.
- Outlier scoring and explanations.
- Parent-group aggregation.
- Deliverable adapters and test fixtures.

Start as one ticket with these explicit seams. Split it into smaller tickets
if any seam requires independent design, implementation, or validation.

## Progress

Claimed for implementation on 2026-08-30. The first slice is the shared
read-only analysis interface over SQLite: callers should provide a database
path and receive normalized rows/groups through a small, testable module
interface. Existing analysis modules will remain adapters until the shared
interface is validated; migration will follow in subsequent slices.

Implemented `scripts/insights/analysis_queries.py` and its isolated temporary
database tests in `test_analysis_queries.py`. The interface currently exposes
normalized observations with annual/numeric filters, canonical parent groups,
multi-entity groups, and a combined-input convenience function. The first
slice passes independently; consumer migration and deeper query seams remain
open work on this ticket.

## Completion criteria

- Existing consumers migrate without changing their public CLI behavior.
- Queries are tested through the shared interface, not by duplicating SQL in
  each consumer.
- HTML/PDF results reconcile with the shared query results.
- Refresh and full insights tests remain green.

## Resolution (2026-09-01)

- Extended `analysis_queries.py` with shared annual-observation, integrity, and
  refresh-metadata seams while retaining explicit interim-period handling.

  `AnalysisQueries`, including IN-010, IN-012, IN-016, IN-017, IN-018, IN-020,
  IN-021, IN-022, IN-023, IN-024, trend diagnostics, review diagnostics,
